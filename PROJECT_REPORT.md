# Project report — Insurance Claims Intelligence

What was built, how it works, which data and prompts were used, what we iterated on, and what we learned.

Related docs: [README.md](README.md) (quick start) · [SETUP_WINDOWS.md](SETUP_WINDOWS.md) (Windows setup)

## 1. Project overview

### Problem

Claims investigation mixes structured facts (policy dates, listed coverages, estimate arithmetic, missing documents) with unstructured policy language (exclusions, duties after loss, coverage clauses). A pure chatbot invents numbers; a pure retrieval app cannot run claim workflows. This project combines both under a **tool-calling agent** with a hard safety rule: **never approve, deny, settle, or pay**.

### What we built

A local **Agentic Hybrid RAG** MVP:

| Layer | Stack |
| --- | --- |
| UI | React + TypeScript + Vite + React Flow |
| API | FastAPI + SSE event stream |
| Agent | LangGraph loop (LLM ↔ tools) |
| Chat / embeddings | Nebius Token Factory (OpenAI-compatible) |
| Dense vectors | Pinecone |
| Sparse retrieval | Local BM25 over policy Markdown chunks |
| Fusion | Reciprocal Rank Fusion (RRF) |
| Claim / policy facts | Local synthetic JSON (deterministic tools) |

### End-to-end flow

1. User selects a claim (or **None** for portfolio) and a question in the UI.  
2. UI `POST /api/investigate` → backend starts a run and streams SSE events.  
3. LangGraph agent (system prompt + tools) decides which tools to call.  
4. Policy-language questions go through **Hybrid RAG** (`search_policy_documents`).  
5. Structured questions use deterministic tools (dates, coverages, estimate math, docs, similarity, portfolio).  
6. Agent must finish with `generate_investigation_report`.  
7. React Flow canvas lights up from real tool/node events; bottom panel shows the report for **human review**.

```
UI (React Flow + report panel)
  → FastAPI (/api/investigate + SSE)
    → LangGraph agent (Nebius chat, tool_choice=auto)
      → Deterministic tools (local JSON)
      → Hybrid RAG (BM25 + Nebius embed + Pinecone + RRF)
      → generate_investigation_report → human review
```

### Two investigation modes

| Mode | Claim ID | Typical tools | RAG? |
| --- | --- | --- | --- |
| Claim-scoped | e.g. `CLM-1001` | claim details, dates, coverage, estimate, docs, optional policy search | Yes, when policy text is needed |
| Portfolio | `none` / empty | `query_portfolio_data` | No — answers from the full book JSON |

### Safety posture

- Reports always set `human_review_required=true`.  
- Disclaimers state that date checks and “coverage listed” flags are **not** legal coverage determinations.  
- Estimate nets are illustrative; duplicates are flagged, not auto-removed.  
- Payment / settlement amounts are out of scope.

## 2. Datasets used

All operational data is **synthetic**, generated by `backend/scripts/generate_data.py` with fixed seed `42` for reproducibility. No real policyholder PII or production claim files.

### Scale (after generate)

| Asset | Count / location | Role |
| --- | --- | --- |
| Policies | 5 (`POL-5001` … `POL-5005`) | Structured metadata + Markdown forms |
| Policy Markdown | `backend/data/policies/*.md` | Hybrid RAG corpus (Declarations, definitions, Collision/Comp/Liability, exclusions, duties, endorsements) |
| Claims | 15 (`CLM-1001` … `CLM-1015`) | Investigation scenarios |
| Claim documents | ≥30 records | Submitted vs required checklist |
| Repair line items | ≥40 rows | Estimate math + duplicate-charge demo |
| Required-doc checklist | collision / comprehensive / default | Missing-document tool |
| Evaluation questions | 20 (`EQ-01` … `EQ-20`) | Offline + UI evaluation set |

### Scenario tags (designed edge cases)

| Claim | Tag | Why it exists |
| --- | --- | --- |
| CLM-1001 | `standard_collision` | Happy-path demo: active policy, Collision listed, complete docs |
| CLM-1002 | `no_collision_coverage` | Collision **not** listed (Comprehensive only) |
| CLM-1003 | `policy_expired` | Loss date after expiration |
| CLM-1004 | `comprehensive_hail` | Comprehensive / hail path |
| CLM-1005 | `duplicate_line_items` | Duplicate ADAS calibration on estimate |
| CLM-1006+ | glass, theft, flood, vandalism, historical, etc. | Breadth for similarity and portfolio stats |

### Indexes (built by ingest)

| Index | How | Used by |
| --- | --- | --- |
| BM25 | `ingest_docs.py` or `build_bm25_only.py` → `backend/data/indexes/` | Sparse lexical retrieval |
| Pinecone | `ingest_docs.py` → index `claims-intelligence`, namespace `policy-docs` | Dense semantic retrieval |

Chunking defaults: size **800**, overlap **120**. Hybrid defaults: BM25 top-k **8**, dense top-k **8**, RRF top-k **6**, RRF *k* **60**.

### What is *not* a dataset

Nebius models and Pinecone are **services**, not training corpora. The agent does not fine-tune; it calls a tool-capable chat model and an embedding model at runtime.

## 3. Prompts and agent instructions

Source of truth: `backend/app/agent/prompts.py` plus per-run user messages in `run_investigation()` (`backend/app/agent/graph.py`).

### System prompt (summary of rules)

The agent is instructed to:

1. **Answer the user’s question first** — do not expand into a full FNOL narrative unless asked.  
2. **Use tools for facts** — do not invent policy text, dates, deductibles, counts, or citations.  
3. **Portfolio mode** — if claim ID is missing / none / portfolio, call `query_portfolio_data`; put counts in `policy_facts` and a dataset summary citation in `retrieved_evidence`.  
4. Prefer `search_policy_documents` when policy *language* is needed for a known policy.  
5. For effective/expiration vs accident-date questions: call `get_claim_details`, `validate_policy_dates`, **and** `search_policy_documents` so citations exist.  
6. For “is Collision listed?”: call `check_coverage_facts` and state clearly listed / not listed.  
7. **Always finish** with `generate_investigation_report`.  
8. `claim_summary` = direct 1–3 sentence answer with key dates/facts.  
9. Put structured tool facts in `policy_facts`; put RAG / portfolio citations in `retrieved_evidence` (not raw tool JSON).  
10. Leave estimate / missing-docs / similar-claims sections empty unless the question needs those tools.  
11. Never approve/deny/settle/pay; never claim date or coverage flags alone establish legal coverage; escalate gaps in `unresolved_questions`.

Full text lives in `SYSTEM_PROMPT` in `prompts.py`.

### Per-run user message (claim mode)

```
Claim ID: {claim_id}
Question: {question}

Answer this Question only. Call only the tools required for it, then finish with
generate_investigation_report. Put the direct answer (with key dates/facts) in
claim_summary — do not write a full accident narrative unless the Question asks for one.
```

### Per-run user message (portfolio mode)

```
Claim ID: none (portfolio / dataset question — no single claim selected)
Question: {question}

Use query_portfolio_data to answer from the full policies/claims dataset.
Do not assume a single claim's policy. Finish with generate_investigation_report
using claim_id='portfolio'. Put the direct answer (counts and IDs) in claim_summary.
```

### Force-report nudge

If the model stops without calling `generate_investigation_report`, a `force_report` graph node appends a user message that **requires** the report tool, restates that `claim_summary` must answer the question in 1–3 sentences, and keeps `human_review_required=true`.

### Tool schemas as soft instructions

OpenAI-style function schemas in `tools.py` reinforce the same product rules — especially `generate_investigation_report`:

- `claim_summary`: direct answer, not a generic full claim narrative  
- `retrieved_evidence`: citation objects (`document_name`, `excerpt`, …)  
- `human_review_required`: must be true  

Chat call settings: `tool_choice="auto"`, `temperature=0.1`, `max_tokens=2500`, with a max tool-call bound (`MAX_TOOL_CALLS`, default 12).

## 4. Iterations we tried

Development was iterative; the current code still shows the scars of earlier failures. Rough progression:

### Iteration A — Core agentic shell

- FastAPI + LangGraph agent ↔ tools loop  
- Synthetic policies/claims + Markdown policy forms  
- Nebius chat with function calling  
- React UI with a workflow canvas  

**Learning:** A free-form “write a report” assistant was too loose; forcing a final **report tool** made the UI contract stable.

### Iteration B — Hybrid RAG for policy language

- Chunk Markdown → BM25 locally + embeddings → Pinecone  
- Fuse with RRF; filter by `policy_id`  
- Tool: `search_policy_documents`  

**Learning:** Lexical BM25 catches form language (“Effective Date”, “Section 3”); dense search helps paraphrases. Fusion beat either alone for citation demos. Embedding dimension must match the Pinecone index — changing embed models without a new index name caused mismatches.

### Iteration C — Deterministic tools for numbers

- Dates, listed coverages, Decimal estimate math, missing docs, similar claims  
- Offline evaluator (`evaluate.py`) that grades tools without the LLM  

**Learning:** LLMs should not do deductible arithmetic or inventory counts. Tools keep answers auditable and make unit tests possible without burning API credits.

### Iteration D — Prompt / UX: “answer the question”

Symptoms: agent rewrote the full accident story for every question; canvas looked busy with unused tools.

Changes:

- System + user prompts: answer the question only; call only needed tools  
- Report schema description tightened for `claim_summary`  
- Example questions split into claim vs portfolio lists in the API  

### Iteration E — Portfolio mode

Symptoms: “How many policies are active?” with no claim selected still latched onto a single claim.

Changes:

- `query_portfolio_data` tool  
- Explicit portfolio user message and UI claim = None  
- Portfolio citation backfill from `policies.json`  

### Iteration F — Reliability hardening

Symptoms: empty `retrieved_evidence`; model skipped the report tool; Pydantic exploded on weird LLM JSON shapes; Windows reload left stale tool bindings; ports 8000/5173 stuck.

Changes:

| Fix | Where |
| --- | --- |
| Citation backfill from RAG / dates / portfolio tool messages | `_ensure_report_citations` |
| `force_report` graph node + deterministic fallback report | `graph.py` |
| Report builder as plain dicts (`v5_plain_dict`) with citation coercion | `generate_investigation_report` |
| Import `tools` module (not bound functions) + rebuild graph each run | reload safety |
| Fail-fast Nebius tool-calling validation | `validate_tool_calling()` |
| `dev.ps1` frees ports; `-SkipSync` for fast restarts | local DX |
| BM25-only ingest path without cloud keys | `build_bm25_only.py` |

### Iteration G — Docs and developer path

- Consolidated Windows setup, fixed broken `docs/` links  
- One-command `dev.ps1` + separate backend/frontend scripts  
- This project report for assignment / handoff

## 5. Learnings and observations

### Workflow design

1. **Hybrid architecture fits claims.** Structured tools for facts; RAG for policy wording; agent only for routing and natural-language packaging.  
2. **The report tool is the contract.** Streaming events and the UI report panel both depend on a structured final tool call, not free text.  
3. **Prompting alone is not enough.** Backfills, force-report, and plain-dict builders were required when the model omitted citations or malformed JSON.  
4. **Mode separation matters.** Portfolio vs claim-scoped questions need different tools and different user prompts; otherwise the agent “grounds” on the wrong claim.  
5. **SSE + React Flow is excellent for demos.** Stakeholders can see *which* tool ran and inspect I/O instead of trusting a black-box paragraph.  
6. **Safety language must be repeated** in system prompt, tool descriptions, report disclaimer, and UI copy — models still drift toward sounding decisive.  
7. **Offline eval is complementary.** Keyword/`expected_contains` grading on tools is cheap and stable; full LLM-on-LLM eval is optional and flakier.  
8. **Local-first DX on Windows** needs explicit care: execution policy, port zombies with `--reload`, uv vs venv, and clear `.env` model IDs from the real Nebius catalog.

### Observations from running investigations

- For date questions, requiring both `validate_policy_dates` and `search_policy_documents` produced better `retrieved_evidence` than dates alone.  
- Coverage “listed / not listed” answers are most reliable when the agent actually calls `check_coverage_facts` (see EQ-02 / EQ-06 style checks).  
- Duplicate-line detection on CLM-1005 is a strong visual demo of why estimate math should stay deterministic.  
- Over-calling tools still happens on vague questions (“full investigation”); prompt + “call only what you need” reduces but does not eliminate it — the max tool-call cap is a necessary backstop.

### What we would improve next

- Stronger routing (explicit planner node or constrained tool subsets per question type)  
- Optional reranker (`ENABLE_RERANK` exists but is off)  
- Richer citation UI (highlight chunk in policy Markdown)  
- Live LLM evaluation harness with rubric scores, not only string contains  
- Persistence of runs (today the event bus is in-memory)
